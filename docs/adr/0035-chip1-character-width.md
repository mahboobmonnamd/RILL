## Context

ADR 0023 shipped Chip 1 v0 as one column per scalar so M4 could close without a
width-source decision. That decision is now due: T-CHIP1-WIDTH-DEFERRED exists
so the miss is falsifiable, and M7 must not swap the live chip while CJK and
emoji still misalign against Chip 0.

[SPIKE-WIDTH](../SPIKE-WIDTH.md) measured the two candidates ADR 0023 D5 named.

- `'日本X'` is **5** columns under UAX #11 (`W`/`F` → 2) and under
  `unicode-width` 0.2.2 `str.width`. Chip 1 v0 reports **3**.
- Family ZWJ `👨‍👩‍👧‍👦`: `str.width` is **2**; summing `char.width()` is **8**.
  Chip 1 v0 clusters to **1** column. Width is a property of the **cluster**.
- Ambiguous (`α`, `■`) is 1 under `width()` even with the crate's default
  `"cjk"` feature; that feature adds `width_cjk()`, it does not change `width()`.
- Chip 0 already expands to one `PodCell` per column. The host treats
  `codepoint == 0` as space. `PodCell` is 16 bytes; 13 attr bits are free.
- `unicode-width` as `[dependencies]` fails the ADR 0020 D2 test: Chip 1 exists
  so this tree does not live on an external Unicode/emoji cadence. Its
  `tables.rs` is ~1.56 MiB because it encodes ZWJ, regional indicators, keycaps
  and tags, not a plain East Asian Width array.

Hand-written CJK `match` ranges remain forbidden (ADR 0023 D5, ADR 0017 D2).

## Decision

### D1 — Cluster, then width

A printable cluster occupies `W` columns, where `W` is 1 or 2. Combining marks
(Unicode categories Mn and Me), ZWJ (`U+200D`), variation selectors
(`U+FE00..=U+FE0F`, `U+E0100..=U+E01EF`), a printable immediately following
ZWJ, and a regional-indicator pair (`U+1F1E6..=U+1F1FF`) append to the open
cluster and MUST NOT consume a new cell.

Width is computed for the cluster, not by summing per-scalar widths. The first
scalar that opens a cluster decides placement: East Asian Width **Wide** or
**Fullwidth** → 2 columns, otherwise 1. Subsequent appends do not add columns
(ZWJ family stays 2; `e` + U+0301 stays 1). A second regional indicator MAY
expand a lone RI from 1 column to 2 on the same row; it MUST NOT split the
pair across rows.

This is still **not** full UAX #29. Indic conjuncts, Brahmic aksaras, keycap
sequences, and emoji-presentation promotion by VS16 are **named misses**.
Devanagari `क्ष` may occupy 1+1 if only EAW is applied to the scalars.
`RILL_GRAPHEME_MAX` remains 32; beyond it: keep the base, increment
`grapheme_truncated`, never silently drop, never a fixed stack buffer
(ADR 0023 D2, unchanged).

Cite UAX #11 and the emoji ZWJ rule. T-CHIP1-GRAPHEME stays.

### D2 — Generated data in this tree; Unicode version pinned

East Asian Width W/F (and Mn/Me for clustering) are generated by
`scripts/gen-east-asian-width.py` from Python `unicodedata`, emitted as Rust
ranges in `crates/vt-engine/src/east_asian_width.rs`. Humans do not edit the
table. The generated file is **committed**, so `fast.yml` needs no Unicode
download.

The Unicode version is pinned in `third_party/unicode.pin` next to
`third_party/ghostty.pin` discipline (ADR 0002 D7): moving it is its own PR,
with T-CHIP1-WIDTH re-run. The generator MUST refuse to emit if
`unicodedata.unidata_version` does not match the pin. `scripts/lint-planes.sh`
(via `fast.yml`) runs `scripts/gen-east-asian-width.py --check` and MUST fail
if the committed `east_asian_width.rs` differs or if Python's unidata does not
match the pin. A skip is a failure (ADR 0002 D5).

### D3 — `unicode-width` is a `[dev-dependencies]` secondary oracle only

`unicode-width` MUST NOT appear under `[dependencies]` or
`[build-dependencies]`. It MAY appear under `[dev-dependencies]`,
`default-features = false` (do not pull `"cjk"` / `width_cjk`).

A gate MUST NOT be expressed only as "equals `unicode-width`". The primary
oracle is `snapshot()`: cursor column and lead/tail cells against values
written in the test (ADR 0012 D7). Divergence (Ambiguous, Brahmic,
`width_cjk`) is named in SPEC-VT-SCREEN §9.

`scripts/lint-planes.sh` gains `no-unicode-width-at-runtime`.

### D4 — Ambiguous → 1

East Asian Width Ambiguous, Neutral, Narrow, and Halfwidth occupy **1**
column. Do not silently enable `width_cjk`. A locale switch is a later ADR,
not M7.

### D5 — Two cells, attrs bits 3 and 4; `PodCell` stays 16 bytes

A wide cluster occupies two columns on the same row:

- **Lead** holds the base scalar. `attrs` bit3 (`1 << 3`) is wide-lead.
- **Tail** is a continuation the presenter must not atlas as its own glyph.
  `attrs` bit4 (`1 << 4`) is wide-tail. Tail `codepoint` is the same base
  scalar as the lead. It MUST NOT be `0`: the host paints `codepoint == 0` as
  space, so a zero tail would blank the second column and leave the lead
  one cell wide (SPIKE-WIDTH Result 4).
- Empty cell remains space `32` with no wide bits. `_pad` stays zero.
- T-CHIP1-POD (`size_of == 16`, `align_of == 4`) stays green.

SGR bits 0–2 are unchanged (bold, underline, inverse). The host presenter
honours bits 3–4 at live-swap time so CJK is two cells on GPU. Chip 0 may
leave those bits 0 until it is removed from the warm path. That paint work
is **not** this ADR.

`repaint_bytes` MUST skip wide-tail cells so a second instance replaying the
emit expands the lead again and does not double-width.

ECH, DCH, or a print that lands on a wide lead or tail MUST smash **both**
halves to space and the current background so no orphan tail remains. The
required mutation is `orphan_wide_tail` (skip the smash).

### D6 — A wide cluster MUST NOT split across rows

If remaining columns on the cursor row are fewer than the cluster width,
apply pending-wrap / DECAWM as ASCII does (SPEC-VT-SCREEN §2), **then** place
the whole cluster. With DECAWM on, that means wrap to the next row first.
With DECAWM off, if the cluster still does not fit, do not place it (do not
write the lead on this row and the tail on the next).

### D7 — T-CHIP1-WIDTH replaces T-CHIP1-WIDTH-DEFERRED

**T-CHIP1-WIDTH** — feed `日本X` into an 80×24 Chip 1; `cursor_col == 5`;
cells: `日` lead col 0 + tail col 1, `本` lead col 2 + tail col 3, `X` col 4.
The test's doc comment cites this ADR. Additional named fixtures: ZWJ family
width 2 (`fixtures/bytes/zwj_emoji.bin`; fail if absent), wide wrap at the
last column. Combining `e` + 40× U+0301 stays `cursor_col == 1` under
T-CHIP1-GRAPHEME.

**Required mutation.** `RILL_MUTATE=narrow_cjk` — force one column per scalar
(v0 behaviour). That MUST turn T-CHIP1-WIDTH red, proving the gate observes
the cursor and the lead/tail cells, not a constant. `wide_advances_two` is
removed; it inverted the deferred gate and would now be a no-op (or a
self-fulfilling green).

M7 still MUST NOT swap the live chip until T-CHIP1-WIDTH is Proven (ADR 0023
D4's *precondition* survives; the *deferral* does not). The live-swap ADR
MUST cite T-CHIP1-WIDTH as Proven. This ADR does not authorize that swap.

### D8 — Pending cluster is bounded state, not an input-sized buffer

An open cluster is `Screen.open_cluster`: row, column, length, ZWJ/RI flags,
and the width already placed. It survives `feed()` so a combining mark or ZWJ
in the next `feed()` still appends. It does **not** store cluster scalars.
`snapshot()` after the first `feed()` of `日` already shows width 2 (lead +
tail); the engine MUST NOT buffer until the cluster closes. Length is capped
by `RILL_GRAPHEME_MAX` (32). There is no allocation proportional to input
for pending combining marks. Hostile: 40 combiners after a base still
truncate and increment `grapheme_truncated`.

## Consequences

- zsh, `less`, `vim`, `htop`, and CJK/emoji column layout become representable
  on Chip 1's POD grid. Paint still belongs to the presenter at M7.
- Chip 1 stays isolated. No host or daemon link.
- Unicode cadence is ours: bump the pin, regenerate, review the range diff.
- Indic conjuncts remain a named miss until a later ADR.

## Rejected alternatives

- **`unicode-width` as `[dependencies]`.** Rejected: re-imports Unicode/emoji
  cadence into the crate whose job is to own it (ADR 0020 D2, SPIKE-WIDTH
  Result 5). Throughput is irrelevant; width is a lookup on `print`.
- **Summing `char.width()` / per-scalar EAW without clustering.** Rejected:
  ZWJ family becomes 8 columns (SPIKE-WIDTH Result 2).
- **Hand-written CJK `match` ranges.** Rejected: compiled-from-memory catalog
  (ADR 0023 D5, ADR 0017 D2).
- **Ambiguous → 2 / silent `width_cjk`.** Rejected: product choice is western
  UTF-8 `wcwidth`; a locale switch is a later ADR.
- **Grow `PodCell` or use `codepoint == 0` as tail.** Rejected: ABI lock
  (T-CHIP1-POD) and the host's zero-as-space paint (SPIKE-WIDTH Result 4).
- **Full UAX #29 in this slice.** Rejected: the terminal subset in D1 is what
  the spike measured; Indic conjuncts are a named miss.
- **Link Chip 1 as live, or honour wide bits in the host here.** Rejected:
  M7 + packaged CJK look ([#272](https://github.com/mahboobmonnamd/RILL/issues/272),
  [#305](https://github.com/mahboobmonnamd/RILL/issues/305)).
- **Sixel / ReGIS / Kitty / iTerm images, Ghostty exec, a second VT.**
  Rejected by ADR 0012 D5 and ADR 0050 D5.
